Node-RED na prática

Aula de IoT: do zero até um painel que mostra os dados de um sensor em tempo real.

Este é o roteiro da aula, desenhado como um fluxo do Node-RED. Clique em um bloco para ir até a etapa. Quando você concluir uma etapa, aparece um pontinho verde embaixo dela.

Etapa 1

O que é o Node-RED e para que serve

O Node-RED é uma ferramenta gratuita para criar programas arrastando blocos e ligando eles com fios, em vez de escrever muitas linhas de código. Ele foi criado na IBM em 2013, é de código aberto e roda direto no navegador (Chrome, Edge, Firefox).

Pense numa linha de montagem: a peça entra numa ponta, passa por várias máquinas e cada máquina faz um trabalho. No Node-RED, a “peça” é uma mensagem com dados (por exemplo, a temperatura de um sensor), e cada máquina é um bloco que faz alguma coisa com ela.

Sensor envia 32 °C Está acima de 30? Liga o ventilador

As 5 palavras que você vai usar a aula toda

Nó (node)
Cada bloquinho colorido. Um nó faz uma única tarefa: gerar um dado, fazer uma conta, mostrar o resultado…
Fio
A linha que liga um nó ao outro. É por ele que a mensagem viaja, sempre da esquerda para a direita.
Fluxo (flow)
O conjunto de nós ligados por fios. É o seu “programa”.
Mensagem (msg)
O pacote de dados que passa pelos fios. O valor principal fica guardado em msg.payload (payload = “carga”).
Deploy (Implementar)
O botão vermelho que salva e coloca o fluxo para funcionar. Mudou alguma coisa? Clique em Deploy, senão a mudança não vale.

E onde entra a IoT?

IoT (Internet das Coisas) é ligar objetos do dia a dia à internet: sensores, lâmpadas, motores, câmeras. O problema é que esses objetos falam “línguas” diferentes e alguém precisa juntar tudo. O Node-RED faz esse papel de central. Com ele dá para:

  • Receber dados de placas como ESP32, Arduino e Raspberry Pi (por MQTT, HTTP, porta serial…).
  • Criar regras: “se a umidade do solo ficar baixa, liga a bomba d’água”.
  • Montar painéis com gráficos e botões, que abrem até no celular.
  • Enviar alertas por e-mail, Telegram ou WhatsApp, e guardar dados em planilhas ou bancos de dados.

Exemplos reais: estufa inteligente, casa automatizada, monitoramento de máquinas numa fábrica, estação meteorológica da escola.

Etapa 2

Ligando o Node-RED com o Docker

Em vez de instalar o Node-RED peça por peça, vamos usar o Docker. Ele roda programas dentro de uma “caixa” pronta, chamada contêiner. É como uma marmita: já vem tudo montado, é só esquentar.

Vamos usar a caixa oficial do Node-RED (a imagem nodered/node-red). Na primeira vez, leva uns 5 a 10 minutos.

Como funciona o copiar e colar aqui

Cada comando aparece numa caixa azul igual à janela do PowerShell. Clique em Copiar, vá até o PowerShell, cole com Ctrl + V (ou clique com o botão direito do mouse) e aperte Enter. O trecho PS C:\Users\aluno> é só o começo da linha que o PowerShell já mostra; ele não é copiado.

  1. Abra o Docker Desktop

    Aperte a tecla ⊞ Windows, digite Docker Desktop e abra. Espere até aparecer, no canto inferior esquerdo da janela dele, Engine running (motor ligado). Pode levar 1 ou 2 minutos. Se pedir login, clique em Skip (pular).

    Deixe o Docker Desktop aberto (pode minimizar) durante toda a aula.

  2. Abra o PowerShell

    Aperte ⊞ Windows, digite PowerShell e clique em Windows PowerShell. Vai abrir uma janela azul (ou preta) com um cursor piscando. É nela que vamos digitar os comandos.

  3. Teste se o Docker está funcionando

    PowerShell
    PS C:\Users\aluno> docker run --rm hello-world

    Se aparecer Hello from Docker!, está tudo certo. Se der erro, veja a lista de problemas no fim desta etapa.

  4. Baixe e ligue o Node-RED

    PowerShell
    PS C:\Users\aluno> docker run -d -p 1880:1880 -v node_red_data:/data --name meu-node-red nodered/node-red

    Na primeira vez ele baixa a imagem (uns 2 a 5 minutos). No fim aparece uma linha comprida de letras e números: é o código do contêiner, sinal de que deu certo.

    O que cada parte do comando faz:

    docker run
    Cria e liga um contêiner novo.
    -d
    Roda “em segundo plano”: você pode fechar o PowerShell que o Node-RED continua ligado.
    -p 1880:1880
    Abre a porta 1880, para o navegador conseguir acessar o Node-RED.
    -v node_red_data:/data
    Cria uma “gaveta” chamada node_red_data onde seus fluxos ficam guardados, mesmo se o contêiner for desligado.
    --name meu-node-red
    Dá um nome para o contêiner, para ligar e desligar depois.
    nodered/node-red
    A imagem oficial do Node-RED, baixada do Docker Hub.

  5. Confira se ele está rodando

    PowerShell
    PS C:\Users\aluno> docker ps

    Deve aparecer uma linha com o nome meu-node-red e, na coluna STATUS, algo como Up 30 seconds (ligado há 30 segundos). Ele também aparece no Docker Desktop, na aba Containers, com uma bolinha verde.

  6. Abra o Node-RED no navegador

    Abra o Chrome, Edge ou Firefox e digite na barra de endereço:

    Endereço do navegador
    http://127.0.0.1:1880

    Também funciona com localhost:1880. Vai aparecer a tela do Node-RED, com uma faixa vermelha no alto. Conseguiu? Então está tudo pronto! ✅

  7. Como desligar e ligar de novo

    O docker run é só para a primeira vez. Depois disso, use estes comandos:

    Desligar
    PS C:\Users\aluno> docker stop meu-node-red
    Ligar de novo (outra aula)
    PS C:\Users\aluno> docker start meu-node-red

    Na próxima aula: abra o Docker Desktop, espere o Engine running e rode o docker start. Seus fluxos continuam lá, guardados na gaveta node_red_data.

    O computador foi “resetado” e o contêiner sumiu?

    Se o docker start disser que meu-node-red não existe, rode de novo o docker run do passo 4 e importe o seu flows.json (veja a Etapa 7) para recuperar os fluxos.

Deu algum erro? Procure aqui

“docker” não é reconhecido

O Docker Desktop não está instalado neste computador. Avise o professor e troque de máquina.

“error during connect” ou “docker_engine: O sistema não pode encontrar o arquivo”

O Docker Desktop está fechado ou ainda iniciando. Abra-o e espere aparecer Engine running, depois tente de novo.

“permission denied” ou “acesso negado” ao rodar docker

Seu usuário não tem permissão para usar o Docker neste computador. Avise o professor.

“The container name "/meu-node-red" is already in use”

O contêiner já foi criado antes. Em vez do docker run, use docker start meu-node-red.

“port is already allocated” (porta já em uso)

Já tem outro Node-RED usando a porta 1880. Rode docker ps para ver se o seu já está ligado (se estiver, é só abrir o navegador). Se for outro programa, troque -p 1880:1880 por -p 1881:1880 no docker run e acesse http://127.0.0.1:1881.

O navegador diz “não é possível acessar esse site”

Rode docker ps. Se o meu-node-red não aparecer, ligue com docker start meu-node-red. Se aparecer, espere uns 20 segundos (ele pode estar iniciando) e recarregue a página. Para ver as mensagens internas do Node-RED, use docker logs meu-node-red.

“pull access denied” ou “repository does not exist”

O nome da imagem foi digitado errado. Use o botão Copiar do passo 4 em vez de digitar.

Etapa 3

Conhecendo a tela do Node-RED

Antes de montar o primeiro fluxo, vale conhecer as quatro áreas da tela. O desenho abaixo é uma versão simplificada do que você está vendo no navegador:

Node-REDDImplementar ▾☰
Afiltrar nós inject debug function switch
BFluxo 1
C🐞 depuração
  • A
    Paleta de nós (esquerda): todos os blocos disponíveis. No alto tem uma caixinha de busca: digite o nome do nó (por exemplo debug) para achar rápido.
  • B
    Área de trabalho (centro): o quadriculado onde você solta e liga os nós. Cada aba no topo (Fluxo 1, Fluxo 2…) é uma folha diferente.
  • C
    Barra lateral (direita): mostra informações. A aba mais usada é a de depuração, com o ícone de inseto 🐞, onde aparecem as mensagens.
  • D
    Botão Implementar/Deploy e menu ☰ (canto superior direito): o botão vermelho coloca o fluxo para funcionar; o menu tem opções como Importar e Gerenciar paleta.

Movimentos básicos

Colocar um nó
Arraste da paleta e solte na área de trabalho.
Ligar dois nós
Clique na bolinha cinza do lado direito de um nó, segure e arraste até a bolinha do lado esquerdo do outro.
Configurar
Dê duplo clique no nó. Ao terminar, clique em Concluído (Done).
Apagar
Clique no nó ou no fio e aperte Delete.
Desfazer
Ctrl + Z.

Como importar um fluxo pronto

Cada atividade tem um código de fluxo pronto. Use se travar em algum passo ou quiser conferir sua resposta:

  1. Clique em Copiar fluxo na atividade.
  2. No Node-RED, abra o menu ☰ e escolha Importar (ou aperte Ctrl + I).
  3. Cole o código na caixa grande (Ctrl + V) e clique em Importar.
  4. Os nós ficam “grudados” no mouse: clique na área de trabalho para soltar.
  5. Clique em Implementar/Deploy.
Etapa 4

Atividade 1: Meu primeiro fluxo

Objetivo: entender como uma mensagem nasce, passa por um fio e aparece na tela. Tempo estimado: 15 minutos.

inject: Clique aqui function: Maiúsculas debug: Ver mensagem

  1. Coloque os dois primeiros nós

    Na busca da paleta, digite inject e arraste o nó azul para a área de trabalho. Depois busque debug e arraste o nó verde para a direita dele.

    O inject é um botão que cria uma mensagem. O debug mostra a mensagem na barra lateral.

  2. Ligue os nós com um fio

    Arraste da bolinha da direita do inject até a bolinha da esquerda do debug. Deve aparecer uma linha cinza ligando os dois.

  3. Clique em Implementar/Deploy

    Depois abra a aba de depuração 🐞 na barra lateral direita.

  4. Aperte o botão do inject

    Clique no quadradinho que fica do lado esquerdo do nó inject. Na aba 🐞 aparece um número enorme, tipo 1790000000000.

    Esse número é a data e hora atual, contada em milissegundos desde 1970. É assim que os computadores medem o tempo!

  5. Troque a mensagem por um texto

    Dê duplo clique no inject. Na linha msg.payload, clique na setinha do tipo e escolha texto (ícone az). Escreva Olá, IoT!. No campo Nome escreva Clique aqui. Clique em Concluído, depois em Deploy, e aperte o botão de novo.

  6. Coloque um nó function no meio

    Clique no fio e aperte Delete para apagá-lo. Busque o nó function (laranja) e coloque entre os dois. Ligue: inject → function → debug.

    Dê duplo clique no function, dê o nome Maiúsculas e, na aba Ao receber mensagem (On Message), apague o que tiver e cole:

    Código do nó function (JavaScript)
    msg.payload = msg.payload.toUpperCase();
return msg;

    Tradução: “pegue o texto da mensagem, transforme em letras maiúsculas e mande adiante”.

  7. Teste

    Deploy, clique no botão do inject e olhe a aba 🐞.

    Resultado esperado

    Aparece "OLÁ, IOT!" na aba de depuração.

Etapa 5

Atividade 2: Sensor de temperatura simulado

Objetivo: criar um “sensor de mentirinha” que manda uma temperatura a cada 2 segundos, e uma regra que separa temperaturas normais das quentes. Tempo estimado: 25 minutos.

Por que simular? Porque assim dá para aprender a lógica sem precisar de nenhuma placa ou sensor físico. Depois, é só trocar o simulador por um sensor de verdade.

A cada 2 segundos Sensor de temperatura Está quente?
🔥 Quente
✅ Normal

  1. Crie uma aba nova

    Clique no + ao lado da aba “Fluxo 1”. Assim a atividade 2 fica separada da 1.

  2. Faça o inject disparar sozinho

    Arraste um inject e dê duplo clique. Em Repetir (Repeat), escolha intervalo e coloque a cada 2 segundos. Marque também Injetar uma vez após 1 segundo. Nome: A cada 2 segundos. Concluído.

  3. Crie o sensor

    Arraste um function, ligue depois do inject, dê o nome Sensor de temperatura e cole este código:

    Código do nó function
    // Gera uma temperatura aleatória entre 20 e 35 °C
let temperatura = 20 + Math.random() * 15;

// Arredonda para 1 casa decimal
msg.payload = Math.round(temperatura * 10) / 10;
msg.topic = "temperatura";
return msg;

    As linhas que começam com // são comentários: explicações para humanos, o computador ignora.

  4. Crie a regra com o nó switch

    O switch (amarelo) funciona como uma bifurcação na estrada: ele manda a mensagem para um caminho ou outro, dependendo de uma condição.

    Arraste um switch, ligue depois do sensor e dê duplo clique. Nome: Está quente?. Na primeira regra, escolha > e digite 30 (tipo número, ícone 09). Clique em + adicionar no rodapé e, na nova regra, escolha caso contrário (otherwise). Concluído.

    Repare que agora o switch tem duas bolinhas de saída: a de cima é “maior que 30”, a de baixo é “o resto”.

  5. Coloque um debug em cada saída

    Arraste dois nós debug. Ligue a saída de cima a um deles e dê o nome 🔥 Quente. Ligue a saída de baixo ao outro e dê o nome ✅ Normal.

  6. Implemente e observe

    Clique em Deploy e abra a aba 🐞. A cada 2 segundos chega uma temperatura, e o nome do debug mostra se ela foi para o caminho “Quente” ou “Normal”.

    Resultado esperado

    Temperaturas como 32.4 aparecem com o nome 🔥 Quente; temperaturas como 24.1 aparecem com ✅ Normal.

    As mensagens vão encher a tela. Para pausar, clique no quadradinho verde do lado direito de cada nó debug (ele desliga aquele debug) e clique em Deploy. Para limpar a aba 🐞, use o ícone de lixeira.

Etapa 6

Atividade 3: Painel de controle da estufa

Objetivo: criar uma página com um medidor e um gráfico da temperatura, e um interruptor para ligar uma lâmpada. É assim que se monta o painel de um projeto de IoT de verdade. Tempo estimado: 30 minutos.

A cada 2 segundos Sensor
Medidor
Gráfico
Interruptor: Lâmpada Texto: Estado

Parte A: instalar os nós de painel

O Node-RED não vem com os nós de painel. Vamos instalar o Dashboard 2.0, pelo próprio navegador:

  1. Abra o gerenciador de paleta

    Menu ☰ → Gerenciar paleta (Manage palette) → aba Instalar (Install).

  2. Procure e instale

    Na busca, digite:

    Nome do pacote
    @flowfuse/node-red-dashboard

    Clique em Instalar e confirme. Espere a mensagem de sucesso e feche a janela.

    Como saber se deu certo

    Role a paleta da esquerda até o fim: deve aparecer uma categoria nova chamada dashboard 2, com nós como ui-gauge, ui-chart, ui-switch e ui-text.

    Deu erro na instalação?

    Algumas redes bloqueiam esse download. Não fique tentando de novo: avise o professor.

Parte B: montar o painel

  1. Traga o sensor da Atividade 2

    Crie uma aba nova (+). Volte à aba da Atividade 2, selecione o inject e o function do sensor (segure Ctrl e clique nos dois), copie com Ctrl + C, volte à aba nova e cole com Ctrl + V.

    Dica: desligue os debugs da Atividade 2 para a aba 🐞 não ficar poluída.

  2. Adicione o medidor (ui-gauge)

    Arraste um ui-gauge e ligue na saída do sensor. Dê duplo clique e configure:

    • Group: se já vier preenchido (ex.: Group 1), ótimo. Se estiver vazio, escolha Add new ui-group…, clique no lápis ✏️ e depois em Adicionar. Se ele pedir Page e UI, faça o mesmo: lápis e Adicionar.
    • Type: Half Gauge. Label: Temperatura. Units: °C.
    • Range: mínimo 0, máximo 50.

    Clique em Concluído.

  3. Adicione o gráfico (ui-chart)

    Arraste um ui-chart, ligue também na saída do sensor (uma saída pode ter vários fios!). Duplo clique: escolha o mesmo Group, Label Histórico, Type Line. Concluído.

  4. Adicione o interruptor da lâmpada (ui-switch)

    Arraste um ui-switch para um espaço vazio, abaixo do sensor. Duplo clique: mesmo Group, Label Lâmpada da estufa. Em On Payload troque para texto e escreva LIGADA; em Off Payload, texto DESLIGADA. Concluído.

    Name ou Label?

    Name é o nome que aparece só no editor. Label é o texto que aparece no painel. Se no painel aparecer “switch”, é porque o Label ficou vazio.

    Não ligue o sensor neste nó!

    O interruptor é um botão que você clica no painel. Por isso a bolinha da esquerda dele fica sem nenhum fio. Ele começa um fluxo novo, separado do sensor.

  5. Mostre o estado da lâmpada (ui-text)

    Arraste um ui-text e coloque à direita do nó Lâmpada da estufa. Ligue a bolinha da direita da Lâmpada da estufa na bolinha da esquerda do ui-text. Duplo clique no ui-text: mesmo Group, Label Estado:. Concluído.

    No fim, sua tela deve ter dois fluxos separados:

    Carimbo de data/hora Sensor de temperatura
    Temperatura
    Histórico
    Lâmpada da estufa Estado:

    Viu um triângulo vermelho em cima de algum nó? Ele está sem configuração. Quase sempre é o Group vazio: dê duplo clique no nó e escolha o grupo.

  6. Implemente e abra o painel

    Clique em Deploy. Abra uma nova aba no navegador com o endereço:

    Endereço do painel
    http://127.0.0.1:1880/dashboard
    Resultado esperado

    Um painel com o ponteiro do medidor se mexendo a cada 2 segundos, um gráfico desenhando a linha da temperatura e um interruptor que, ao ser clicado, muda o texto para LIGADA ou DESLIGADA.

    Mas cadê a lâmpada?

    Nesta aula a lâmpada é simulada: o interruptor é o comando (“quero ligar”) e o Estado é a resposta (“está LIGADA”). Num projeto real, a saída do interruptor iria até uma placa, como um ESP32 com um relé, e aí uma lâmpada de verdade acenderia. Isso fica para as próximas aulas, com MQTT.

Use o fluxo pronto ou monte à mão, não os dois

Se importar o fluxo pronto depois de ter montado o seu, o Node-RED pode criar dois painéis no mesmo endereço. Nesse caso, apague um deles.

Desafio: uma lâmpada que acende de verdade na tela

Na busca da paleta, digite template. Vão aparecer dois nós com esse nome: use o azul, da categoria dashboard 2 (ícone </>), e não o laranja da categoria função, que não aparece no painel. Arraste o azul e ligue na saída do nó Lâmpada da estufa (pode deixar o ui-text ligado também). Duplo clique: escolha o mesmo Group, apague o conteúdo do campo Template e cole:

Código do ui-template
<template>
  <div style="text-align:center">
    <div :style="{
      fontSize: '72px',
      filter: msg.payload === 'LIGADA'
        ? 'drop-shadow(0 0 18px gold)'
        : 'grayscale(1) opacity(0.3)'
    }">💡</div>
    <b>{{ msg.payload || 'DESLIGADA' }}</b>
  </div>
</template>

Deploy e abra o painel: com o interruptor ligado, a lâmpada brilha em amarelo; desligado, ela fica cinza e apagada.

Como montar o arquivo

  1. Crie o documento

    Abra o Word (ou o Word pelo próprio Teams/Office online) e crie um documento em branco. No topo, escreva seu nome completo, sua turma e a data.

    Salve com o nome no formato NodeRED_NomeSobrenome_Turma, por exemplo NodeRED_AnaSouza_3A.

  2. Parte 1: cole os prints das etapas concluídas

    Escreva um título antes de cada print, para o professor saber o que é:

    • Docker: o PowerShell mostrando o resultado de docker ps, com o meu-node-red ligado.
    • Atividade 1: o fluxo no editor e a aba 🐞 mostrando "OLÁ, IOT!".
    • Atividade 2: o fluxo no editor e a aba 🐞 com mensagens de 🔥 Quente e de ✅ Normal.
    • Atividade 3: o fluxo no editor e o painel aberto em /dashboard, com o interruptor ligado.

  3. Parte 2: cole as questões e responda

    Clique no botão Copiar as questões (acima), cole no documento e escreva suas respostas embaixo de cada “Resposta:”.

  4. Salve como PDF

    No Word: Arquivo → Salvar como → no tipo, escolha PDF → Salvar. O PDF abre igual em qualquer computador, sem bagunçar os prints.

  5. Exporte seus fluxos (recomendado)

    No Node-RED: menu ☰ → Exportar → escolha todos os fluxos → Baixar. Vai ser salvo um arquivo flows.json na pasta Downloads. Ele também serve de backup: se o computador do laboratório for apagado, você importa esse arquivo e recupera tudo.

Para onde ir depois

Você montou o caminho completo de um sistema de IoT: dado chega → regra decide → painel mostra → usuário controla. Nas próximas aulas, o sensor de mentirinha vai virar um sensor de verdade:

  • MQTT: o “correio” da IoT, usado para placas como o ESP32 mandarem dados para o Node-RED pela rede (nós mqtt in e mqtt out).
  • ESP32 + sensor DHT11/DHT22: medir temperatura e umidade reais.
  • Alertas: mandar mensagem no Telegram quando a estufa esquentar demais.

Material oficial (em inglês): nodered.org/docs e dashboard.flowfuse.com.
